# Общие правила

- отвечай кратко.
- запрещено писать комментарии и javadoc в коде.
- запрещено просматривать каталоги сборки (build).
- запрещено читать содержимое каких-либо файлов, кроме тех, на которые явно дано разрешение. это касается и агентов Explore и Plan. передавай им явно этот запрет. запрет не действует на примеры кода, данные в скиллах.
- запрещено исследовать структуру проекта за пределами каталога, в котором открыта текущая сессия. это касается и агентов Explore и Plan. передавай им явно этот запрет.
- при использовании/вызове/наследовании существующего кода смотри только его сигнатуру через MCP, не читай детали реализации.
- если получаешь ответы на вопросы, то сохрани ответы в спеку в раздел "ответы на вопросы" в краткой форме.
- при выполнении задания сначала пиши тесты.
- запускай gradle-задачи через обертку gradlew.
- после написания кода запусти тесты (gradle test), проверь тестовое покрытие (gradle check) и стилистику кода (gradle detekt).
- если надо прочитать скилл, то загрузки его через инструмент Skill.
- для исследования структуры проекта и чтения файлов используй в первую очередь MCP.

# Применяемые подходы

- Domain-Driven Design
- Value Objects
- Clean Architecture
- Either (arrow.core)
- TDD
- Детройтская школа тестирования
- JUnit 5 + Kotest (shouldBe assertions)
